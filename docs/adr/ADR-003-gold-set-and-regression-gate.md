# ADR-003: ゴールドセットは手作りで検証し、Recall の回帰を CI で止める

**ステータス:** Draft  
**決定日:** 未確認（遡及記録: 2026-10-28）  
**review_by:** 2026-11-17

> 雛形: [ADR-000-public-template](https://github.com/flipslidersand-labs/repo-compass/blob/master/docs/adr/ADR-000-public-template.md)。遡及して書いた記録で、当時の比較経緯は推定していない。

## 課題

評価の結論は、使う質問セット（ゴールドセット）の質で決まる。質問と正解の箇所をどう作り、
評価が悪化したときにどう気づくかを決める必要があった。

## 決定

1. ゴールドセットは手作りし、各質問の正解スパンを、実際のチャンクの本文と突き合わせて検証する（19 クエリ・10 論文）。
2. Recall@5 がどちらかの方式で閾値（0.95）を下回ったら、`check_regression.py` が exit 1 で CI を失敗させる。

## 理由

- 手作りなら、正解の根拠を人が確認できる。
- 回帰チェックは、評価条件の変更で結果が悪化したときに、気づかず通ることを防ぐ。
- **却下した代替案:** 自動生成の質問セット。比較した記録はない（当時の理由は未確認）。

## 影響

- **限界:** 19 クエリでは両方式の Recall@5 が 1.0 に張り付き、Recall では方式の差が判別できない（README の結果表）。
- 難問のゴールドセット（`eval/gold_set_hard.json`、40 件、#194/#197）が追加された。Issue #201 は、そこでの BM25 のみの結果を
  nugget の Recall@5 が 0.125、full-chunk が 0.525（354 チャンク、2026-10-28）と記録している。この値は
  このリポの README にはまだ反映されておらず、ここでは報告値として扱う（再現は未確認）。
- 難問の結果を踏まえると、README の「nugget の導入を推奨」は、19 クエリの範囲での結論として読む必要がある。

## 再検討条件

難問を加えた結果が README に反映されたとき、または回帰チェックの閾値を新しいゴールドセットに合わせるとき（#194 の受入条件）。
