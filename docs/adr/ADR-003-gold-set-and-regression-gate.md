# ADR-003: ゴールドセットは手作りで検証し、Recall の回帰を CI で止める

**ステータス:** Draft  
**決定日:** 未確認（遡及記録: 2026-10-28）  
**review_by:** 2026-11-17

> 雛形: [ADR-000-public-template](https://github.com/flipslidersand-labs/repo-compass/blob/master/docs/adr/ADR-000-public-template.md)。遡及して書いた記録で、当時の比較経緯は推定していない。

## 課題

評価の結論は、使う質問セット（ゴールドセット）の質で決まる。質問と正解の箇所をどう作り、
評価が悪化したときにどう気づくかを決める必要があった。

## 決定

1. ゴールドセットは手作りし、各質問の正解スパンを、実際のチャンクの本文と突き合わせて検証する（19 クエリ・10 論文）。
   難問セット（`eval/gold_set_hard.json`。起草 40 件 → 確認後 37 件）は例外で、サブエージェントが起草した。span の実在は機械で検証済みだが、質問の妥当性（語彙の非共有・一意性・前提）は人の確認が要る（下記「影響」、#194）。
2. Recall@5 がどちらかの方式で閾値（0.95）を下回ったら、`check_regression.py` が exit 1 で CI を失敗させる。

## 理由

- 手作りなら、正解の根拠を人が確認できる。
- 回帰チェックは、評価条件の変更で結果が悪化したときに、気づかず通ることを防ぐ。
- **却下した代替案:** 自動生成の質問セット。比較した記録はない（当時の理由は未確認）。

## 影響

- **限界:** 19 クエリの旧結果（先頭 200 字の断片）では両方式の Recall@5 が 1.0 に飽和し、方式の差が判別できなかった。実チャンク全文では nugget 0.842（窓 0）に下がる（README「評価の前提」の表）。
- 難問のゴールドセット（`eval/gold_set_hard.json`、人の確認後の 37 件、#194/#197）で再現した（BM25 のみ・PDF 全文プール 354 チャンク、#198 修正後、2026-10-31 に再集計）:
  nugget の Recall@5 は 0.216、full-chunk は 0.514（確認前の 40 件では 0.200 / 0.525）。0.125 は #198 修正前の値。結果は README に反映済み。
- 失敗の最大要因は検索（37 件中 18 件）で、nugget 固有の失敗は 11 件（分割 2・抽出 9）。nugget だけの改善では full-chunk の 0.514 を超えられない（#201）。
- **難問の人の確認は途中。** 起草 40 件のうち、12 件を人が判定（○9・×3）、15 件は Claude が原文を読んで案を出し（×2・△4・○9。人は未確認）、13 件は Claude が原文を読んで確認し○のまま（人は未確認）。外したのは人が判定した 3 件。Claude の案で一度外した 2 件（11・16）は、一意性の判断が誤りだったため復元した（評価は span の部分一致なので、同一文が複数あっても問題にならず、文が違う場合は span を共通部分に変えれば残せる）。△の 4 件は 2026-10-31 に直した。数値は 37 件で再集計済み。人の確認が進めば、件数と数値は変わるため、暫定として扱う。
- AI（Codex）に同じ確認をさせて較正したが、人が不採用にした 3 件を 1 件も拾えなかった（#194）。この確認は人の判定で行う。
- README の「nugget の導入を推奨」は撤回済み。易しい質問では同等、難問では nugget が劣る、が現在の結論。

## 再検討条件

難問を加えた結果が README に反映されたとき、または回帰チェックの閾値を新しいゴールドセットに合わせるとき（#194 の受入条件）。
